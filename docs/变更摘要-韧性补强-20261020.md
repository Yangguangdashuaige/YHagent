## 各项要点

### 1. LLM 流建立重试
- **问题**：主调用一次失败整个请求作废，而网络抖动/限流是最常见瞬时故障
- **边界**：只在首 token 前重试——出字后打字机已播报，中途重试会内容重复。重试安全窗口的本质是"零副作用窗口"
- **行为**：失败 → 日志 → 等 2s（ctx 取消则放弃）→ 重试一次 → 仍失败才报错

### 2. 向量化失败降级纯 BM25
- **问题**：embedding 服务一抖，search_knowledge 整个不可用
- **方案**：向量化失败时置 `queryVec = nil`，`Search(nil)` 天然跳过向量通道，BM25 关键词通道独立工作
- **收益**：检索可用性不受嵌入服务影响，只损失语义泛化能力；混合检索双通道架构当初就埋好了这条逃生通道，本次只是接上

### 3. stale-while-error
- **问题**：上游三角洲接口失败且缓存已过期时，用户直接拿到错误
- **方案**：cache 新增 `GetStale`（返回条目即使已过期）；doGet 失败路径回吐过期数据，包裹为 `{"_stale":true,"_note":"数据源暂时不可用，以下为缓存的历史数据","data":…}`
- **价值观**："10 分钟前的价格"几乎总是好于"查询失败"。缓存 TTL 管数据新鲜度，stale 回吐管服务可用性——两者是不同的 SLO
- **可观测**：trace 新增 `stale_served` 字段（观测页可见回吐次数）

### 4. 重排熔断（rerankBreaker）
- **问题**：Viking 免费额度 2026-11-17 到期；到期后每次检索都要白等 8s 超时才回退 RRF，P99 延迟翻倍
- **方案**：连续失败 3 次（成功即清零）→ 熔断 10 分钟，期间直接跳过重排走 RRF 原序；冷却期过后自动放行试探恢复
- **要点**：熔断保护的是**回退路径本身**——回退逻辑若每次都要先经历一遍超时，回退就名存实亡。熔断让"额度消失"从事故降级为静默降级

### 5. 联网搜索 24h 结果缓存 + ingest 批次重试
- **问题**：玩家对新活动/新收藏品反复追问，同一查询每次都付 5-15s 联网调用；ingest 向量化批次失败会让整次入库（含已成功批次）作废
- **方案**：web_search 结果按原始查询串缓存 24h（惰性过期清理）；缓存命中**同样推送候选卡片**，入库确认链路不缺席；ingest 批次对齐 indexer 的"失败 3s 后重试一次"策略
- **注意**：缓存键为模型生成的查询串原文，换词即 miss，不存在错误结果被长期锁定的问题

## 风险与回滚

- 全部改动无配置项、无数据库迁移、无协议变更，回滚即 revert 单个 commit
- 唯一行为变化在失败场景：原本报错的地方现在返回降级数据（stale 回吐有 `_stale` 标注，模型会向玩家说明数据滞后）
