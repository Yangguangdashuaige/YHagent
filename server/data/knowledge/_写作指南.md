# 静态知识库写作指南（本文件不会被建库，下划线开头自动跳过）

把你从 Wiki / 公众号 / 视频整理的攻略写成这个目录下的 `.md` 文件即可。
文件命名建议：`序号-主题.md`，例如 `01-新手入门.md`、`02-M14武器攻略.md`。

## 建库与生效流程

1. 在本目录新增或修改 `.md` 文件（本指南和 README 不会被收录）；
2. 在 `server/` 目录运行：`go run ./cmd/indexer`；
3. 重新构建/部署服务端：`go build ./cmd/server`（网页和索引都编进二进制）；
4. 完成。玩家提问时 AI 会自行判断是否检索知识库。

## 写作规范（直接影响检索质量）

- **一篇文档一个主题**，用 `#` 写文档大标题，`##` / `###` 分节。
  每片资料会带上标题路径（如"武器攻略 > M14 > 压枪技巧"），标题要具体、说人话。
- **每节控制在几百字**。系统会自动按约 600 字切片，表格、代码块、列表不会被拆散。
- **数值类内容优先用表格**，例如：

  | 配件 | 后坐力控制 | 开镜速度 | 备注 |
  |---|---|---|---|
  | 垂直握把 | +15% | -2% | 新手推荐 |

- **关键词写全**：第一次出现用"全名（简称/黑话）"，如"烽火地带（烽火）"、
  "M14（射手步枪）"，方便玩家用不同说法都能搜到。
- **只写确定的事实**，时效内容（如"当前版本"）标注版本号/日期；
  实时价格、密码这类动态数据**不要写进知识库**，它们由三角洲 API 工具实时查询。
- 一篇文档的开头可以用 2~3 句话概括本文适用的问题，例如：
  "本文解答新手在烽火地带模式中如何配装、如何撤离、死亡后损失什么。"
  这能显著提升"配错关键词"时的命中率。

## 从网页整理的建议

- Wiki 页面直接复制正文到 Markdown，把页面标题转成 `#` 标题；
- 视频字幕整理时，去掉口癖和重复内容，按主题重新分段；
- 每篇文档末尾可留一行 `> 整理日期：2026-09-22`，方便日后判断资料是否过时。
